## Evidence

  voices through the OpenAI-only compatibility set, and performs one uncached provider call per HTTP
  request.
- `public/app.js:1524-1540` sends `{ text, audioConfig }` for hosts and adds speaker/tone only for
  seats; the host supplies no campaign id, so the server cannot resolve canonical profiles.
- `server.js:124-132` preserves bracketed model text; Grok interprets that syntax as delivery tags.

## Predicted observable failure

A Grok campaign can send an invalid OpenAI voice, the host and seat can hear different identities,
host profile resolution silently falls back, hostile/model-written bracket directives reach the TTS
provider, and every listener pays for identical synthesis independently.

## What

Replace the audio boundary and minimum client call shape together: resolve every voice server-side
from authoritative campaign state, neutralize bracket syntax, enforce provider capabilities, and
deduplicate canonical synthesis across concurrent and recent listeners.

## Approach

The server now accepts only canonical campaign/preview segments, derives campaign identity from the
seat credential (or a required host campaign id), and resolves the narrator/NPC profile against the
active provider. It removes client bracket directives before composing server-owned delivery tags,
publishes authenticated capability/catalog endpoints, validates OpenAI MP3 responses, and keys a
bounded in-flight/completed cache on the complete effective synthesis. The browser and admin panel
use the new boundary; the client sends no voice id or free-text direction.
