# v-1: Grok provider and provider-isolated voice configuration

**Severity**: HIGH — Grok cannot synthesize through the registered seam today, and the single stored
voice-key slot can send one vendor's credential to another vendor after a provider switch.
**Status**: Merged
**Branch**: `fix/v-1-grok-provider-config`
**Implementation commit**: `d744736`
**Merge commit**: `7d55b77`

## Evidence

- `tts-providers.js:85` registers only `openai`; `listTtsProviders()` therefore cannot expose Grok.
- `server-config.js:85-87` resolves one scalar stored `voiceApiKey`, always falling back to
  `OPENAI_API_KEY`, independently of `voiceProvider`.
- `admin/admin.html:135-145` exposes only OpenAI and one generic voice-key field.

## Predicted observable failure

Selecting Grok cannot produce speech because no implementation is registered. Retrofitting only the
provider switch while retaining the scalar key slot can forward an OpenAI key to xAI or an xAI key to
OpenAI. Existing stored OpenAI keys can also be lost if the configuration shape changes without a
legacy read/save path.

## What

Add the pinned Grok provider/request contract and make voice provider metadata and credentials
provider-aware while preserving the existing OpenAI route contract for the later v3 cutover.

## Approach

The provider registry now owns each vendor's voice catalog, reserved narrator, model capability,
request limit, and synthesizer. Grok dispatches directly to the pinned xAI endpoint with only its
supported request fields and rejects successful responses whose bytes are not MP3. Compatibility
exports keep the production `/api/audio/narrate` route OpenAI-shaped until v3 changes the route and
minimum client together.

Voice credentials now persist as `voiceApiKeys: { openai, grok }`. Effective configuration resolves
the active provider before selecting either its stored key or its matching environment fallback;
Grok never falls back to `OPENAI_API_KEY`, and Grok has no effective model. Legacy scalar
`voiceApiKey` rows read as OpenAI-only and rewrite to the nested shape on the next save. Blank,
replace, and explicit-null clearing semantics are independent per vendor. The admin UI exposes the
two masked key slots and hides the OpenAI-only model field when Grok is selected.
