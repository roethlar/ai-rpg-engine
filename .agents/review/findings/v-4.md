# v-4: Provider-aware browser narration queue and canonical player controls

**Severity**: HIGH — the browser aborts the remaining GM narration after one failed run, cannot batch
Grok's per-line delivery tags, and still presents player voice/direction controls that no longer have
authority.
**Status**: In progress
**Branch**: `fix/v-4-browser-voice-queue`
**Implementation commit**: pending

## Evidence

- `public/app.js:1521-1549` makes one request per line and throws out of the loop on the first failed
  request, silently dropping every remaining line.
- `public/app.js:1524-1533` never fetches provider capabilities or sends `expectedProvider`, so it
  cannot use Grok batching or recover deterministically from an admin provider switch.
- `public/index.html:376-405` and `public/app.js:28-30,167-179` still store and display a player voice
  id and free-text direction even though v-3 correctly ignores both.

## Predicted observable failure

One transient synthesis failure makes the GM stop speaking for the rest of the turn; Grok pays the
latency of one call per line instead of batching adjacent speech while preserving tone; a provider
switch can reject a stale queue without bounded recovery; and players are falsely offered per-player
voice/accent controls for a campaign-canonical GM.

## What

Move grouping and queue policy into a browser-safe pure helper used by production and tests, add
fail-closed capabilities and bounded provider-race recovery, continue after failed runs, remove the
obsolete player authorities, and document the canonical OpenAI/Grok voice setup.

## Approach

`public/voice-narration.js` now owns the production policy as browser-safe pure functions. It bounds
and splits fallback text, groups only adjacent same-speaker lines within both provider and aggregate
server limits, and preserves each segment's tone. Missing, timed-out, unknown, or internally
inconsistent capabilities fail closed to provider-agnostic singleton runs. One provider mismatch
may refresh capabilities; a second degrades the remainder to singletons without another fetch or
loop. Failed synthesis/playback runs report once and are skipped while later runs continue.

`public/app.js` executes that helper, sends `expectedProvider`, and resolves an active playback when
Skip cancels it so the queue cannot hang. The settings model and HTML retain only the narration
enable toggle and canonical preview; stale local voice/direction properties are dropped. README now
documents server-owned OpenAI/Grok configuration and shared campaign-canonical playback.
